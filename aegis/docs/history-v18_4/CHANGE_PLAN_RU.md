# AEGIS v17 — интеграция трёх карт

## 1. Фон загрузки
Мини-план: источник → соотношение сторон → читаемость → отдельная проверка.
Использован второй кадр пользователя, assets/img/loading.jpg. Статичный JPEG, center/cover: без дополнительной 3D-сцены. Подсказка F в исходном кадре не ретушировалась. Название загрузки соответствует выбранной карте.
Источник: https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/background-size

## 2. «В бой» в паузе
Мини-план: пункт меню → активный генерал → пауза симуляции → возврат → перенос состояния.
Пункт pBattle добавлен после «Продолжить». Выбор не возрождает бойца и не меняет его экипировку. Назад/Escape возвращают в исходную паузу. Переход на карту сохраняет выбранного генерала.
Источники: https://gameprogrammingpatterns.com/state.html ; https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/

## 3. Окно трёх карт
Мини-план: расширение → три колонки → точные ID → проверка ПК-разрешений.
Ровно stroyka_zarechye_v2, forest_map_camp, angar_map; без пагинации и ANGAR-07. Карточки запускают реальные адаптеры окружения из предоставленных HTML карт. Четыре ПК-разрешения проверяются отдельным UI-стендом, не измеряющим игровой FPS.
Источник: https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/minmax

## 4. Полигон → генерал → бой
Мини-план: единый инвентарь → снимок текущего расхода → загрузка окружения → восстановление → обратный переход.
Шесть слотов, конфигурации оружия, текущие магазины/патронник/резерв, выбранный тип патрона, выбранный слот и использованные гранаты передаются отдельно для каждого из четырёх генералов. Пустая экипировка остаётся пустой. Никакой независимый стартовый комплект карты генералу не выдаётся.
Переход — перезагрузка страницы с временным снимком в sessionStorage, ограниченным текущей вкладкой и одним часом. Это не бесшовный стриминг. Позиции, разрушения, ранения и текущее состояние AI предыдущей локации не сохраняются: начинается новая локация. Оружейная по-прежнему намеренно пересобирает комплект при его изменении.
Источники: https://gameprogrammingpatterns.com/component.html ; https://developer.mozilla.org/en-US/docs/Web/API/Window/sessionStorage

## 5. Чужие руки, оружие и HUD
Мини-план: отделить геометрию → исключить старый загрузчик → подключить ядро AEGIS → проверить запуск и расход.
Вместо iframe с чужой игрой подключаются только js/maps/*: геометрия, материалы, статические коллизии, ветер/трава/вода окружения. Старые FPS-контроллеры, viewmodel, HUD 100 HP, оружие и ввод карт не запускаются. Работают исходные системы AEGIS: бойцы, руки, слоты, оружие, эффекты, звук, медицина, баллистика и движение. Модели конечностей не переделывались. Баллистика и физика проверяются в отдельных стендах tools/.
Источник: https://gameprogrammingpatterns.com/component.html

## 6. Дрон и артудар
Мини-план: исключить исходные entry points → не подключать их UI и hotkeys → проверить состав модулей.
Нет запуска дрона, управляемого артударного режима или их обработчиков карт. Геометрическая функция artillery в лесных модулях строит неподвижное орудие как декорацию; это не артудар и не стрельба. Гранаты и взрывы AEGIS сохранены.
Источник подхода к жизненному циклу: https://gameprogrammingpatterns.com/component.html

## 7. Дополнительные бойцы
Мини-план: общая фабрика → безопасные точки → навигация → видимость → стрельба общим контроллером → проверка симуляции.
На каждой карте четыре генерала и восемь дополнительных бойцов, по четыре на сторону. Это не прежние 40/80 солдат с карточек. Солдаты используют модели и AK-74 AEGIS; у генералов только их собственная экипировка. Бойцы не добавлены в список генералов. Навигация: ограниченный A* по клеткам со статическими коллизиями, не более 1600 раскрытий за поиск; проверки видимости распределены во времени. Стрельба вызывает обычный контроллер AEGIS; есть запрет выстрела при союзнике на линии.
Это базовый боевой AI, не полноценная проверенная тактика штурма/обороны/захвата флага. Длительная массовая битва ещё требует игровых испытаний.
Источник: https://www.redblobgames.com/pathfinding/a-star/implementation.html

## 8. Производительность и графика
Мини-план: отдельный стенд окружения → запуск всех карт → сквозной тест → регрессии → честные ограничения.
Сохраняется геометрия и материалы исходного окружения; общие renderer, камера, погода и постобработка принадлежат AEGIS, поэтому точное пиксельное совпадение со старой автономной картой не обещается. Настройка AEGIS «Ультра-низкая» соответствует potato, а не максимальному качеству. Число бойцов ограничено явно, скрытого обещания 80 бойцов нет.
Смена страницы освобождает прежний WebGL-контекст, не оставляя параллельные движки. В окружении используются существующие instancing/слияние статической геометрии и сетка коллизий. Нативные Ammo-физика разрушения, ткань/динамические объекты автономных карт не перенесены; нельзя выдавать это за сохранение всех их функций. Разрушаемость каждого старого объекта не гарантирована.
На реальных слабых ПК тестов нет. SwiftShader/CPU throttling — программная проверка в одной Linux-среде, не эмуляция конкретной видеокарты. Гарантии «без лагов и без потери графики» нет. После смены качества окружения нужен новый вход на карту; один applySettings не пересобирает её растительность.
Источники: https://threejs.org/manual/en/optimize-lots-of-objects.html ; https://threejs.org/manual/pages/cleanup.html

## Технические файлы
- js/app/maps.js — адаптер коллизий, спавны, переходы.
- js/maps/*.js — извлечённые модули окружения, без автономных игр.
- js/polygon/30c_combat.js — базовый AI поверх контроллеров AEGIS.
- tools/map-environment-stand.html — изолированный запуск геометрии.
- tools/map-extraction/*-closure.json — манифесты выбранных/исключённых объявлений.
- tools/map-tests/ — итоговые отчёты и воспроизводимые проверки.
