# Живое тело · 18.4.3 · экспериментальная ветка

**Полный перенос НЕ завершён. Это обновлённый физический стенд, а не готовая замена персонажей в бою.**

В обычной игре сохраняется режим версии 18.4: KCC, анимационные цели, IK и Rapier. Новый `GActiveBody` автоматически не включается ни у команды, ни у противников. Надёжное вставание, нормальная боевая скорость и улучшение игрового FPS пока не заявляются.

## Запуск

1. Распаковать **всю** папку AEGIS отдельно от предыдущей версии.
2. Windows: `start-body-lab.bat`. Linux/macOS: `./start-body-lab.sh`.
3. Обычная игра: `start-server.bat` / `./start-server.sh`.
4. Нужны Python 3.8+ и браузер с WebGL 2. Node.js/npm для игры не нужны. Не открывать `index.html` через `file://` — браузер блокирует загрузку модулей Recast и WASM.

Сервер привязан только к `127.0.0.1`, выбирает свободный порт 8000…8019 и открывает браузер. Ручной путь стенда: `/index.html?activebodylab&map=angar_map`. Окно сервера оставлять открытым.

Стенд сначала на паузе. Доступны выбор персонажа, одиночный кадр, боковые толчки 6/60 Н·с, **продольный толчок 60 Н·с**, расслабление, попытка вставания, медленная ходьба, падение с высоты и реальные коллайдеры. Мышь вращает камеру, колесо меняет расстояние. Отображаются нагрузка на каждую стопу, контакты ладоней/голеней, режим решателя и завершённые/пропущенные шаги.

**«Сброс» пересоздаёт исходную позу; это НЕ физическое вставание.** Физика всегда шагает по 1/60 с. Частота 20/30/60 Гц в интерфейсе меняет группирование этих шагов, а не физическую модель.

## Новое относительно 18.4.2

- **Самоколлизии** не соседних частей тела. Ладони могут сталкиваться с торсом, противоположные голени — друг с другом. Исключены близкие по дереву связи и перекрывающиеся элементы центрального корпуса. Это не детальная коллизия пальцев, одежды и снаряжения. Таблицы исключений вычисляются один раз при создании, а не внутри каждого контакта.
- **Шарнирные локти** с запретом бокового скручивания и ограниченным сгибанием. Физические пределы локтей и коленей проверяются после падения на четырёх масштабах и трёх частотах группирования шагов.
- **Фактическая нагрузка на стопы** из нормальных контактных импульсов Rapier. Для отрыва ноги нужны контакт опорной стопы, достаточная суммарная нагрузка, перенос основной доли веса и допустимое положение capture point. Одного таймера больше недостаточно.
- Контакты ладоней, предплечий и голеней регистрируются отдельно. «Контакт голени» не обязательно означает контакт именно коленной чашечки.
- **Безопасная передача в свободное физическое падение.** Выявлен сбой Rapier 0.19.3 при разборке multibody по отдельным связям. Переход теперь пересоздаёт динамический ragdoll из точного снимка: положения, вращения, линейные/угловые скорости, массы и коллайдеры сохраняются. Тест сравнивает каждый компонент до/после; сброса позы или обнуления скорости нет. Идентификаторы физических тел при этом меняются. Это передача между решателями, а не способ встать.
- У расслабленного тела не выполняются повторные перенастройки уже выключенных моторов. Цели стойки не используются как воздушная опора, когда обе стопы не имеют контакта.
- Убраны неудачные прототипы подъёма и обход условия опоры по таймеру. Начало выпрямления требует измеренной нагрузки, положения центра масс и наклона. **Это делает проверку честнее, но не завершает вставание.**
- Улучшена диагностика стенда; исходник контроллера отформатирован. Добавлены отдельные тесты самоколлизий/нагрузки/передачи в падение и CPU-бенчмарк.

## Как устроено тело

В стойке используются 19 динамических сегментов с гравитацией 1, 18 multibody-связей и 18 вспомогательных impulse-joints с угловыми моторами. Колени — шарниры X, локти — шарниры Y. При падении остаются 19 динамических сегментов и 18 impulse-joints с сохранёнными шарнирными ограничениями.

Нет кинематического таза, KCC у подключённого экземпляра, подвеса к миру, компенсации гравитации или коррекции живого тела через `setTranslation`/`setLinvel`. При передаче между решателями исходные значения задаются только новым телам из точного снимка. Геометрический IK вычисляет **угловые цели моторов**, а не перемещает кости рендера. Визуальный скелет читает реальные интерполированные вращения Rapier.

Это пока **не** полная физическая анатомия: нет всех физиологических пределов/пределов усилия; пальцы, лицо, одежда и экипировка не получили отдельных динамических тел.

## Производительность: найденное ограничение

Раздельно измеряются управление, шаг Rapier и разбор контактов в Node.js без рендера, ИИ, навигации и боя. Текущие значения — в `tools/advanced-tests/active-body-performance.json`. Это **не FPS игры** и не измерение на компьютере пользователя.

Главный расход экспериментального тела — решатель Rapier, а не TypeScript-логика управления. Вариант с отдельными артикуляциями рук действительно сокращал CPU-время, но нарушил проверку свободного падения центра масс. **Он отклонён и удалён из поставляемого контроллера.** Его замеры сохранены в `docs/rejected-experiments/` только как история неудачного эксперимента, не как заявленный выигрыш этой сборки.

Предел 12 тел — ограничение размещения, не обещание приемлемой частоты кадров. Базовые 8 итераций мира и 12 дополнительных итераций сегментов всё ещё слишком дороги для массового включения. Обычная игра не переведена на этот контроллер автоматически.

## Проверки и оставшиеся задачи

Точные результаты текущего выпуска находятся в `docs/ACTIVE_BODY_QA.json` и отдельных отчётах. Старые отчёты помещены в `docs/history-v18_4*`; они не удостоверяют текущий код.

Результаты текущей версии:

- Сборка, строгий TypeScript, восемь npm-наборов, 15 сценариев инфраструктуры и пять составных вращений моторов: PASS.
- Самоколлизии, измерение опоры, точная передача в падение и очистка: PASS. В отдельной стойке измерено около 778 Н нагрузки стоп против веса тела около 747 Н; это приближённая динамическая оценка, не точные весы.
- Стойка 30 с с боковым толчком 6 Н·с: PASS.
- За 20 с команды ходьбы пройдено около **2.71 м** (ранее 1.34 м в том же тесте), затем устойчивая остановка. Требование **6 м** пока не выполнено: FAIL.
- Отдельный 60-секундный диагностический прогон: команда движения со 2-й до 35-й секунды, **19 завершённых шагов, 0 пропусков, около 4.82 м**, без падения до конца наблюдения.
- Продольный толчок 60 Н·с вызывает падение; надёжного самостоятельного вставания после него нет: FAIL.
- Пять 12-секундных сценариев сильных толчков с разных направлений и падения с 2 м: конечные числа, связность суставов и очистка PASS. Падение в этих сценариях разрешено — это проверка численной устойчивости, а не вставания. Наибольший кратковременный разрыв якорей при падении был около 4.94 см; полноценная проверка анатомии этим не заменяется.
- Четыре игровых пресета: стойка/толчок по 15 с, динамичность и отсутствие скрытой капсулы PASS; ошибок JS нет, WebGL error = 0. Обычный рендер Ангара с камерой/оружием от первого лица также проверен, но это прежний гибридный игровой режим.
- Отдельный CPU-стенд: примерно **15.9 / 63.2 / 188.4 мс** на физический шаг для **1 / 4 / 12** тел. Для 12 тел около **97.4%** стоимости пришлось на Rapier. Это не измерение FPS игры; массовый запуск такого тела ещё не оптимизирован до приемлемого бюджета.

Приёмка полного переноса остаётся **FAIL**, если не пройдена хотя бы одна строгая проверка: 30 с стойки с толчком, 6 м за 20 с команды с последующей устойчивой остановкой, падение от продольного толчка 60 Н·с и самостоятельное устойчивое вставание. Критерии не ослаблены ради зелёного статуса.

Ещё необходимы:

1. Надёжное вставание из разных падений, переход обратно к управляемой артикуляции, компенсационные шаги и автоматическое восстановление.
2. Боевая скорость, бег, приседание, ползание, прыжки, ступени/склоны и перелезание.
3. Полные ограничения и допустимые усилия остальных суставов, физический хват оружия и взаимодействия.
4. Подключение тела ко всем бойцам, камера от первого лица, лечение/перетаскивание, ранения, смерть и оживление.
5. Приемлемая стоимость 12 тел и полноценные длительные проверки боя на трёх картах. Устойчивость на плоском стенде не доказывает всё перечисленное.

## Проверки разработчика

```sh
npm ci
npm run build
npm run typecheck
npm test
npm run test:active-body:motors
npm run test:active-body:contacts
npm run test:active-body:robustness
npm run test:active-body:acceptance
npm run test:active-body:browser
npm run test:active-body:performance
```

Для CLI нужен Node.js 22+ и TypeScript. Для браузерных тестов дополнительно нужны Playwright, Chromium и запущенный локальный сервер; параметры `BASE_URL` и `CHROMIUM_PATH`. Бенчмарк запускать отдельно, без других тяжёлых процессов.

`test:active-body:acceptance` намеренно возвращает код **1**, пока полный контракт не выполнен. Диагностические `body-controller-probe.cjs`, `body-recovery-probe.cjs` и поиск поз не являются приёмкой: их код 0 означает выполнение расчёта, а не успешную ходьбу/подъём.

Исходник: `src/advanced/active-body.ts`; собранный модуль: `js/advanced/active-body.js`; интерфейс: `js/app/activebodylab.js`. Windows BAT-файлы не исполнялись в Linux. Производительность на видеокарте пользователя и бой с полностью физическими персонажами на трёх картах не измерены.
